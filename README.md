# NL2SQL Explorer

An AI-powered Natural Language to SQL application that allows users to query relational databases using plain English. The application uses Google Gemini and LangChain to generate SQL, validates the generated query for safety, executes approved read-only queries, and returns structured results for analysis and visualization.

## 🚀 Demo

**Live Application:** [nl2sqlexplore](https://nl2sqlexplorer.netlify.app/)

**Backend API:** [render_url](https://nlsqlexplorer.onrender.com)

---

## 🎯 Problem

Working with relational databases often requires users to know SQL.

NL2SQL Explorer allows users to ask questions such as:

> "Show the top 10 customers by total spending."

Instead of writing SQL manually, the application:

1. Understands the user's natural-language question.
2. Provides the database schema to the LLM.
3. Generates a SQL query.
4. Validates the generated SQL.
5. Executes only approved queries.
6. Returns the results.
7. Recommends an appropriate visualization.

## 🔐 SQL Safety

Because SQL is generated by an LLM, the application validates the generated query before execution.

The validation layer checks for:

* SELECT-only operations
* Dangerous SQL commands
* Multiple SQL statements
* Invalid query structures
* Excessive result sizes
* Query execution limits

Examples of blocked operations include:

```text
INSERT
UPDATE
DELETE
DROP
ALTER
CREATE
TRUNCATE
GRANT
REVOKE
```

The goal is to prevent the LLM from generating destructive database operations.

> **Production consideration:** A production deployment should also use database credentials with read-only permissions as an additional security layer.

## 🧠 AI / LLM Workflow

The application uses Google Gemini with LangChain to convert natural-language questions into SQL.

Example:

### User Input

```text
Show the top 10 customers by total spending.
```

### Generated SQL

```sql
SELECT
    customer_id,
    SUM(amount) AS total_spending
FROM payments
GROUP BY customer_id
ORDER BY total_spending DESC
LIMIT 10;
```

The generated SQL is validated before being sent to the database.

## ⚙️ Local Setup

### 1. Clone the repository

```bash
git clone https://github.com/yogeshwarirj/NLSQLEXPLORER.git

cd NLSQLEXPLORER
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

Activate it:

**Windows**

```bash
venv\Scripts\activate
```

**macOS/Linux**

```bash
source venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure environment variables

Create a `.env` file based on `.env.example`.

```env
GOOGLE_API_KEY=your_gemini_api_key
```

Never commit your real API keys to GitHub.

### 5. Run the application

```bash
python api_server.py
```

The API will start locally on the configured port.

* More granular API authentication

* Database connection pooling
* LLM evaluation and monitoring
* Additional SQL parser-based validation

---

## ⚠️ Current Limitations

The current implementation uses in-memory session management.

For a multi-worker production deployment, sessions should be stored in a shared system such as Redis.

The application also relies on an LLM to generate SQL, so generated queries must always pass through validation before database execution.
